# 开放平台配置指引（真实飞书接入）

> 面向真实用户的中文图文步骤：让 GA 的 hfc（GA → 飞书流式卡片桥）在真实飞书中收发消息与卡片。
> 本文只说明**在哪里填什么**；所有密钥**只引用键名，不写明文值**。密钥值存放在 GA 根目录 `mykey.py`。

## 0. 前置条件

- 已按 [README](../README.md) 完成 hfc 安装：`hfc install`（复制插件 + 写配置），`hfc status` 5/5 OK。
- GA 侧已运行飞书前端进程：`python frontends/fsapp.py`（生产已监听 `127.0.0.1:8898`）。
- 一台公网可达的服务器（或内网穿透），用于接收**卡片回调**。

## 1. 创建企业自建应用

1. 打开飞书开放平台：<https://open.feishu.cn> → 右上角「开发者后台」。
2. 点击「创建企业自建应用」：填应用名称（如 `GA Bridge`）、图标、描述，创建。
3. 进入应用详情 → 「凭证与基础信息」页，可见：
   - **App ID**
   - **App Secret**
4. 把这两个值填入 GA 根目录 `mykey.py`（**键名必须精确小写，否则 fsapp 启动即退出**）：
   - `fs_app_id = "…"`（飞书应用 App ID）
   - `fs_app_secret = "…"`（飞书应用 App Secret）
   - 同时确认 `fs_verification_token`、`fs_encrypt_key` 两个键已存在（先留空，第 3 步再填）。

## 2. 启用机器人能力

1. 应用详情 → 「添加应用能力」→ 选择「机器人」→ 启用。
2. 这样应用才能接收用户私聊/群聊消息，并在会话中发送消息卡片。

## 3. 配置事件与回调（核心）

本应用有两条独立通道，请分别配置：

### 3.1 消息事件：长连接模式（无需请求地址）

1. 应用详情 → 「事件与回调」→ 「事件订阅」。
2. 订阅方式选择**长连接模式**：消息事件由飞书主动推送到 fsapp 的长连接，**不需要填请求地址**。
3. 在事件列表勾选 `im.message.receive_v1`（接收用户消息，/llm /llms /new 等 slash 命令入口）。
4. 按页面提示在「权限管理」申请消息读取/发送相关权限（如 `im:message` 系列），随版本发布生效。
   - 注意：事件列表**不存在** `card.action.trigger` 事件——卡片按钮回调走 3.2 的独立「卡片回调」区域。

### 3.2 卡片回调：请求地址（独立区域）

1. 应用详情 → 「事件与回调」→ 「卡片回调」（与事件订阅并列的独立区域）。
2. 请求地址填：
   ```
   http://<你的服务器公网地址>:8898/card/actions
   ```
   - 端口与路径对应 fsapp 内嵌回调端点（`frontends/fsapp.py`：`POST /card/actions` 卡片回调、`GET /card/actions` URL 校验）。
   - 注意：fsapp 端点默认只绑定 `127.0.0.1:8898`，公网请求需在服务器上用 Nginx/Caddy 反代到该端口，或改为对外绑定。
3. **保存前先自检公网可达**（见 3.3），否则保存校验必然失败。

### 3.3 公网可达性自检（保存前必做）

- 在服务器上执行：
  ```
  curl http://<你的服务器公网地址>:8898/card/actions
  ```
  预期返回 JSON 响应（端点可达即返回；带校验参数的 URL 校验见 3.4）。
- 不通时按顺序排查：
  1. 服务器防火墙是否放行 8898（如 `ufw allow 8898`，或 firewalld 对应规则）；
  2. 云厂商安全组入站规则是否放行 8898；
  3. 是否有端口映射/内网穿透（frp、cloudflared 等）把公网 8898 映射到服务器 127.0.0.1:8898；
  4. 或用 Nginx/Caddy 反代 `/card/actions` 到 `127.0.0.1:8898`。

### 3.4 凭据：Verification Token 与 Encrypt Key

1. 在「事件与回调」页找到「加密策略」：**默认关闭**，先点击**开启**，页面才会提供 Encrypt Key（可点击「生成 Encrypt Key」）。
2. 平台展示：
   - **Verification Token**（用于回调校验）
   - **Encrypt Key**（用于回调载荷加密）
3. 把这两个值填入 GA 根目录 `mykey.py`（小写键名，见 §1.4）：
   - `fs_verification_token = "…"`（平台 Verification Token）
   - `fs_encrypt_key = "…"`（平台 Encrypt Key；若不开加密可留空）
   - 注意：`fs_verification_token` 与 `fs_encrypt_key` **至少配置其一**，否则卡片回调端点不会启动（见 §4 安全提示）。
4. 点击「保存」：飞书会向卡片回调地址发送 `url_verification` 校验请求；fsapp 的
   `GET /card/actions?type=url_verification&challenge=…` 会回显 `challenge`，校验通过即保存成功。

### 3.5 发布生效

回到应用详情 → 右上角「版本管理与发布」→「创建版本」→「申请发布」。
发布后配置与权限才生效（企业内部自建应用通常即时可用）。

## 4. 保存后生效与验证

- 飞书后台保存后，卡片回调校验通过即链路生效；应用发布后消息通道（长连接）可用。
- **修改 `mykey.py` 后必须重启 fsapp 进程**（配置在启动时加载，运行中修改不生效）。
- 安全提示：
  - `fs_verification_token` 配置后，fsapp 对回调强制校验 token，不匹配即拒绝。
  - `fs_verification_token` 与 `fs_encrypt_key` **均未配置**时，卡片回调端点拒绝启动（防配置漂移暴露，fsapp 启动日志可见原因）；至少配置其一。
  - `fs_encrypt_key` 配置后，回调载荷按飞书加密协议解密（AES），未配置时明文解析（不建议生产使用）。
  - 所有密钥只存放在 `mykey.py`，不要提交到仓库或写入文档。

## 5. 验收清单（配置后应看到的现象）

在飞书中给机器人发消息，逐项核对：

- [ ] 发送 `/llms` → 收到**模型选择卡**（LLMs 列表 + 每个非当前模型一个可点按钮）
- [ ] 点击模型按钮 → 收到「✅ 已切换到 [序号] 模型名」回执；再发 `/model` 确认当前模型已变更
- [ ] 发送 `/llm` → 收到**流式会话卡**：标题随状态变化，footer 带统计信息
- [ ] 六命令按钮全部可用：`/new`（会话已重置）、`/reset`、`/undo`（已撤销上一步）、`/llm`、`/llms`、`/model`
- [ ] 会话卡随时间持续更新（thinking → tool → answer），完成后 header 变「已完成」

> 若某一步未出现预期现象：先 `hfc status` 确认插件与配置 OK；再确认 fsapp 进程在跑
> （`ss -tlnp | grep 8898`）；最后按 §3.3 确认卡片回调地址公网可达。
